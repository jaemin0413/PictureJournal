남은 핵심 리스크

문제G002의 실제 native share proof가 아직 완전 종료되지 않았다.
AndroidGitHub Actions + Android Emulator로 share intent smoke test 자동화가 가능하다.
iOSiPhone이 없어도 macOS runner + iOS Simulator에서 build/extension 수준 proof는 가능하다.
한계Instagram 앱 → 실제 iPhone 공유 시트 → Share Extension 전체 E2E는 실기기와 signing 없이는 완전 증명하기 어렵다.
결론: 지금 막힌 것은 .env가 아니라 실제 모바일 런타임 proof다. iPhone 실기기만 제외하면 상당 부분은 AI와 CI로 진행 가능하다.

내가 해야 하는 일

  • GitHub repo URL과 Actions 실행 권한을 제공한다.
  • 가능하면 push 또는 PR 생성 권한을 준다.
  • Android Emulator CI 사용을 허용한다.
  • iOS 확인용 macOS runner 사용을 허용한다.
  • 홈서버 배포 전 실제 DB/MinIO env 값을 제공한다.

.env 관련 상태

현재 개발 차단 아님.

  • 로컬 테스트는 dev default로 통과한다.
  • 배포 전에는 실제 값이 필요하다.
  • 필요 값: DB_URL, DB_USERNAME, DB_PASSWORD, STORAGE_PROVIDER, STORAGE_BUCKET, STORAGE_ENDPOINT, STORAGE_ACCESS_KEY, STORAGE_SECRET_KEY.

추천 다음 결정

새 작업 목표를 “모바일 proof 자동화”로 잡고, G002를 최대한 AI/CI로 해소한다.

  • Android proof는 자동화 우선.
  • iOS는 Simulator/macOS proof 우선.
  • 실제 iPhone proof는 명시적으로 후속 보류.

사용자 액션 튜토리얼

  1. GitHub 연결 준비
    저장소 URL을 공유하고, AI가 push 또는 PR을 만들 수 있는 권한을 준다. 권한이 어렵다면 patch/branch 안내만 받아서 직접 적용해도 된다.
  2. GitHub Actions 활성화
    저장소의 Actions 탭에서 workflow 실행을 허용한다. Android proof는 Ubuntu runner + Android Emulator로 먼저 자동화한다.
  3. Android 실기기 테스트
    내 Android 폰에 개발 빌드를 설치하고 Instagram/브라우저/공유 메뉴에서 “앱으로 보내기”를 실행한다. 결과는 앱 로그와 백엔드 share-intake 생성 여부로 확인한다.
  4. iOS 대체 검증 선택
    iPhone이 없으므로 macOS GitHub Actions에서 iOS app/Share Extension build와 Simulator 수준 smoke까지만 증명한다. 실제 iPhone 공유 시트 E2E는 후속 보류로 남긴다.
  5. 배포 전 env 제공
    홈서버에 올릴 때만 실제 DB/MinIO 값을 제공한다. 로컬 개발 단계에서는 dev default로 충분하다.

React Native / Web / 실기기 구분

  • React Native 앱 화면: Expo/React Native Web을 쓰면 많은 화면은 웹 브라우저에서도 열 수 있다.
  • Android 공유 수신: “공유하기 → 앱으로 보내기”는 네이티브 Android Intent 기능이라 웹 브라우저만으로는 완전 검증할 수 없다.
  • 권장 흐름: UI와 일반 API 흐름은 웹/Expo로 빠르게 확인하고, 공유 수신 proof는 Android 폰 또는 Emulator에서 검증한다.
  • iOS 한계: iPhone이 없으면 실제 iOS 공유 시트 E2E는 불가하다. 대신 macOS runner의 build/simulator proof로 최대한 자동화한다.
정리: “리액트 네이티브라서 웹에서 열 수 있음”은 화면/일반 로직에는 대체로 맞지만, native share receiver 검증은 Android 폰이나 Emulator가 필요하다.

AI 위주 모바일 진행 계획

  1. 모바일 proof harness 생성
    최소 모바일 앱 구조를 만들고 share payload를 백엔드 share-intake API로 보내는 경로를 준비한다.
  2. Android GitHub Actions proof
    Android Emulator에서 share intent를 발생시키고 앱 수신 → API 호출 → artifact 저장까지 자동화한다.
  3. iOS GitHub Actions proof
    macOS runner에서 iOS app과 Share Extension target build를 검증하고, 가능한 Simulator smoke를 수행한다.
  4. CI artifact 기반 증거화
    로그, test result, API response fixture, screenshot 가능분을 artifact로 남겨 G002 재판정 근거로 쓴다.
  5. 실기기 전용 항목 분리
    iPhone + Instagram 실제 공유 시트 E2E는 사용자가 iPhone을 확보할 때 별도 체크포인트로 남긴다.
